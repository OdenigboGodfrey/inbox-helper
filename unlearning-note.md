1. The biggest thing I unlearned while working on my inbox service was the belief that being a good developer means knowing the answer, writing the code and getting it to work. I began to realize that my real value is not how much code I can write from memory, but by how much time it takes me to turn an unclear problem into a reliable and tested solution. AI is changing what that requires from me.

2. I used to approach problems by focusing on the immediate error and trying to fix it. While building concurrency tests for my NestJS inbox service, I encountered problems with Jest's ES module configuration, TypeScript mock types and circular entity dependencies. My first instinct was to keep adjusting configurations and code until the errors disappeared. Working through these problems with AI pushed me to change that approach. Instead of treating every failure as the same kind of problem, I learned to distinguish between tooling issues, incorrect test assumptions, type errors and actual application defects. I also learned that an AI generated fix is only a hypothesis until I understand it and verify it.

3. I also began using AI beyond generating code. I used it to investigate errors, improve test design, question implementation choices and build k6 load tests for the running API. That last step changed my perspective: a unit test can verify a particular behavior, but concurrent load testing can reveal failures that are invisible when requests are executed individually. I am learning to use AI throughout the engineering process, from understanding the problem to validating the result, rather than treating it as an autocomplete tool.

4. I am unlearning is the need to be the person who already knows. I want to become the engineer who learns fastest, tests assumptions early, uses AI to expand what I can accomplish and takes responsibility for what ultimately ships. The goal is not to add AI to my old workflow. It is to rebuild my workflow around better questions, tighter feedback loops, measurable results to produce value as soon as possible the customer base.

5. The AI first shift I felt while working on this demo application was that growth requires pressure and pressure requires short feedback loops. Using AI not as a syntax generator, but as an aggressive architectural sounding board, allowed me to test, break and rewrite entire worker patterns in hours instead of weeks.
